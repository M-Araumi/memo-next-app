# CORSについて

## 1. CORSとは
    オリジン間リソース共有 (Cross-Origin Resource Sharing, CORS) は、追加の HTTP ヘッダーを使用して、あるオリジンで動作しているウェブアプリケーションに、異なるオリジンにある選択されたリソースへのアクセス権を与えるようブラウザーに指示するための仕組み

## 2. なぜCORSが必要なのか
    異なるオリジン間でブラウザからリソースへアクセスする際、ブラウザによるアクセス制御を行うため    

## 3. Memo APIでのCORS設定
    app.use("*", cors({
        origin: "http://localhost:3001",
    }));
    API側で上記のように、すべてのパスに対してCORSミドルウェアを適用し、"http://localhost:3001"からのリクエストを許可するように設定を行なっている

## 4. 今回の通信の流れ
    まずブラウザからAPI側にHTTPリクエストを行う。API側は受け取ったリクエストに対して処理を行い、リクエストに応じたHTTPレスポンスを返す。
    今回の構成では、Next.jsがhttp://localhost:3001、Memo APIがhttp://localhost:3000で動作しているため、異なるオリジン間での通信となる。
    そのため、ブラウザはCORSのルールに基づいて、APIから返されたレスポンスへのアクセスを制御する。

## 5. CORSエラーについて
    Webブラウザが異なるオリジン（ドメイン、プロトコル、ポート番号）間で通信する際、CORSのルールによりレスポンスへのアクセスが許可されていない場合に発生するエラー

## 6. 動作確認
    Webブラウザが異なるオリジン間で通信する際、API側で許可されていないオリジンからのリクエストの場合、ブラウザによってレスポンスへのアクセスが制限され、CORSエラーが発生する。
    今回の構成では、Memo API側でhttp://localhost:3001からのリクエストを許可しているため、Next.jsからのAPI通信が可能となっている。
